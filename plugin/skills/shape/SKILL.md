name: shape
description: Use before building anything of more than a few steps, when the request leaves open what is wanted, why, or what done looks like.
---

Settle what the person wants before you build, with as few questions as the request allows.

## First

- If another skill for shaping a request is already in use in this conversation, follow that one and not this.
- If the person says to just build it, stop shaping at once. Say in one line each call you made for them, then build.

## Read before you ask

- Read what the person pointed at and the code it touches.
- For an area too large to read in passing, send `tune:investigator` with the request and where to look.
- Never ask what the project already answers.

## Say it back

- In a few lines, say what you understood and what you found that bears on the request.

## Ask

- Ask only what would change what gets built.
- One question at a time.
- For the why, ask an open question.
- Where the choices can be named, name them and say which you recommend.

## Stop

- Stop asking once you can state what the thing is for, what done looks like, what is out of scope, and your approach.
- State those four, get a yes, then plan or build.
